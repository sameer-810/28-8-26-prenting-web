# ParentAI — landing site

The marketing page. Vite + React + TypeScript, one route, no framework beyond
that.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # → dist/
npm run verify     # 50 checks against the built page, in a real browser
npm run og         # regenerate public/og.png
```

---

## Before it goes live

Four values nobody can guess. The page renders honestly without them — each one
degrades to something that still works rather than to a dead link — which is
exactly why they are easy to forget.

| What | Where | What it costs while unset |
|---|---|---|
| **Launch domain** | `SITE_ORIGIN` in `vite.config.ts` | `canonical`, `og:url` and `og:image` all point at a domain that may not resolve. Crawlers read the page as a duplicate of nothing. |
| **WhatsApp number** | `site.whatsappNumber` in `src/config.ts` | Every "Ask us" button becomes a `mailto:` link. This page travels *on* WhatsApp; email is a much weaker second. |
| **Play Store URL** | `site.playStoreUrl` | The badge is hidden, so the page never mentions there is an Android app. |
| **App Store URL** | `site.appStoreUrl` | Same, for iOS. |

`npm run verify` reports the WhatsApp fallback explicitly rather than passing
quietly, so an unset number is visible in the output rather than discovered by a
parent.

The domain is **not** in `config.ts`. It lives in `vite.config.ts` because
`index.html` needs it at build time, and `index.html` is deliberately static —
see below.

---

## Why index.html is static

This is a React SPA. WhatsApp's link preview scraper — which is how an Indian
parent will actually receive this page, forwarded in a school group — fetches
the HTML and **never runs a line of JavaScript**. So the title, description,
Open Graph tags, canonical URL and JSON-LD are all written into `index.html`,
with `%SITE_ORIGIN%` substituted at build time by a small Vite plugin.

Anything that matters to a crawler or a scraper has to be in the served HTML.
`npm run verify` reads those assertions off the file on disk, not off the
rendered DOM, so it cannot pass while the share card is blank.

---

## The prices are a copy, and the copy is checked

`src/config.ts` mirrors the plans from the API's `src/config/plans.js`. The app
fetches its prices at runtime so an old build can never quote the wrong number
at the moment of payment; a static marketing page cannot do that and still be
readable by a crawler.

So the numbers are copied — and `npm run verify` fails if they drift. A landing
page advertising ₹499 while the product charges ₹599 is a consumer-law problem,
not a typo.

**If you change a price, change it in both places and run `npm run verify`.**

---

## The og:image

`public/og.png` is generated by `npm run og`, from the same headline the page
carries. Re-run it whenever the `<h1>` or `og:title` changes — a hand-made card
goes out of step the first time the headline is edited, and nobody notices,
because the page looks right and only the shared card is wrong.

It renders at 1200×630 at 1× on purpose: scrapers downscale it to a chat
thumbnail, and WhatsApp rejects oversized images outright rather than resizing
them.

---

## Deploying

Vercel, from this directory. `vercel.json` carries the build command, the
long-cache headers for hashed assets, and a one-day cache for `og.png` so a
regenerated card is picked up without waiting a year.

`public/robots.txt` allows the marketing page and disallows `/login`, `/signup`
and `/admin` — those belong to the app, not to search results.

---

## What `npm run verify` covers

50 checks, in a real browser, against the built output:

- **What a crawler sees** — title, description, OG tags, absolute `og:image`
  (the one that silently breaks WhatsApp cards), canonical, JSON-LD, and that
  the `og:image` file actually exists rather than merely being referenced
- **Price drift** against the API's `plans.js`
- **The claims** — the AI never talks to the child, the 30-minute shape, all
  five phases, boards and grades, the data promises
- **All eight scripts actually render** — Devanagari, Bengali, Tamil, Telugu,
  Kannada, Nastaliq — rather than being described in English
- **Every link resolves**, and the sign-up CTA reaches the app
- **Accessibility** — accessible names, alt text, decorative SVGs hidden,
  heading levels that do not skip, a skip link
- **On a 390px phone** — no horizontal overflow, 44px tap targets
- **Reduced motion** — every section visible immediately, because a
  reveal-on-scroll that fails leaves a blank page rather than a still one
